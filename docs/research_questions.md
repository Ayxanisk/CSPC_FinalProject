# Proposed Research Questions

## Working title

**What Can STEAD Metadata Tell Us About Earthquake Distance and Signal Quality?**

## Why this scope fits the supplied data

The supplied `merge.csv.zip` contains one CSV with metadata for 1,265,657 traces.
It does not contain `merge.hdf5` or another waveform file. In STEAD, the actual
three-component waveform arrays are stored separately in HDF5. Therefore this
project should use metadata-based statistics and curve fitting unless the team
obtains waveform chunks and expands the scope. FFT and waveform-based ML cannot
be performed from this CSV alone.

The archive contains 1,030,231 `earthquake_local` traces and 235,426 `noise`
traces. Noise records have no event magnitudes, source distances, phase picks,
or SNR values, so comparisons involving those variables must use earthquake
traces only. Magnitudes use multiple scales; restricting the magnitude analysis
to `source_magnitude_type == "ml"` avoids mixing unlike scales and leaves
724,824 records in the initial data snapshot.

## Main question

**RQ1. How accurately can the P–S arrival-time difference estimate
source-to-station distance, and does including source depth improve the
estimate?**

- **Variables:** `source_distance_km`, `p_arrival_sample`, `s_arrival_sample`,
  and `source_depth_km` for `earthquake_local` traces with finite values.
- **Derived variable:** `S–P time = (s_arrival_sample - p_arrival_sample) / 100`
  seconds. The 100 Hz sampling rate follows the STEAD dataset description.
- **Models:** compare a linear distance-versus-S–P fit, a quadratic S–P fit,
  and a linear model that also includes source depth.
- **Evaluation:** split by `source_id`, so traces of one earthquake do not occur
  in both training and test sets. Report held-out MAE, RMSE, and R² for all
  models, and inspect errors across distance and depth ranges.
- **Hypothesis:** S–P time increases with distance; depth may explain some of
  the remaining error.
- **Course tools:** use pandas for loading/filtering metadata, NumPy for the
  derived S–P variable and error metrics, SciPy for fitting/comparing models,
  and Matplotlib for the fit and residual plots.

## Secondary question

**RQ2. For local-magnitude (ML) earthquakes, is SNR associated with magnitude
after accounting for source distance and depth?**

- **Subset:** `trace_category == "earthquake_local"` and
  `source_magnitude_type == "ml"`, with valid SNR, magnitude, distance, and
  depth values.
- **SNR handling:** `snr_db` is stored as three component values; define one
  summary per trace (the median of the three components is a robust starting
  choice) and state this definition in the method.
- **Analysis:** plot SNR against magnitude and distance, then fit a regression
  that includes magnitude, log-transformed distance, and depth. Aggregate traces
  by `source_id` so each earthquake contributes one event-level observation.
  Report the magnitude coefficient and its model-based 95% confidence interval.
- **Hypothesis:** at comparable distances and depths, larger-magnitude events
  tend to have higher SNR.
- **Course tools:** use pandas/NumPy to parse the three component values and
  calculate the trace summary, SciPy for correlations and regression, and
  Matplotlib for the magnitude/SNR and residual plots.

## Decision and limits

These two questions are connected: RQ1 studies a timing-based distance signal,
while RQ2 studies how magnitude relates to the quality of recorded earthquake
traces after distance is considered. They fit a short paper and can be answered
with the supplied metadata using statistics and curve fitting. The paper should
not claim FFT or raw-waveform ML results unless waveform data are added.

Initial model estimates and figures are now generated by `src/analysis.py` and
reproducible through the `Snakefile`. Review missing and implausible values,
model assumptions, and event-level uncertainty estimates before treating the
outputs as final conclusions.
